# D3 移动端触控适配：设计与实施记录

> 2026-11-03。承接《触控与UI适配调研》与《D3触控适配逆向调查记录》。
> 目标：从「虚拟手柄点 UI」升级为「真触控」——直接点画面、点背包、点菜单。

## 一、现状盘点（读代码结论）

### 1.2 d2r-mobile 的触控架构（方法论来源，dm_cursor.c 3267 行）

D2R 的幸运：Switch main 保留了 PC **鼠标消息注入**路径（FNV 哈希命名的 InputMessage 直发 UI 根控件）。核心组件：
- `dm_cursor_set_screen`：屏幕坐标 → 光标全局直写（main+0x2d128f8/fc）
- **扣 A 队列**：光标没走到位时按下的 A 排队，到位才放（拖放起点/终点各一）
- **摇杆闭环**：直写坐标会被游戏手柄光标逻辑盖回 → 每次读手柄时推摇杆朝目标走
- **UI 树遍历**（root=main+0x2f05458）判断当前页类型：有自由光标的页才动光标，焦点导航页（设置/任务/对话）整页不动手柄——否则摇杆改设置
- **界面代号**（ui_gen）跨帧控件缓存安全（dm_wref）
- 落位半径 4px、放下重试（多格物品往里挪一格再按，至多两次）

### 1.3 D3 的输入架构逆向结论（见《D3触控适配逆向调查记录》）

- **D2R 式鼠标消息注入不存在**（15 消息名 × 3 哈希全零命中，阳性对照校准过）
- **世界光标可直写**（路线 B）：`0x89d960→0x8a0360→0x9a0370` → 每世界 0x718 结构 +0x170 光标链表，节点 +0/+4/+8 = 世界坐标 xyz
- **UI 是焦点/环选择模式**：无全屏软指针；环形菜单（`RingGlow.Cursor`）+ 方向键焦点高亮
- **UI 事件 = 脚本 VM 函数**：`UI_StashGrid_OnRightClick`、`UI_SkillWalk_OnClick` 等名字注册在 VM（`UI_SkillWalk_OnClick` 的 xref 0x3c619c 处见 intern 模式，调用 0xa49690）
- **PC 键鼠输入层保留**（Mouse1–5/Wheel 键名注册表），点击动作是 PowerSNO 伪技能
- **触摸**：只有 PS4 touchpad 调试残留；**但 nn::hid 触屏读取路径完整**（hle_touch 已实现）

## 二、触控 v1（本次交付，d48b2fe）

**最小通路**：游戏画面触摸 → D3 原生触屏输入。零游戏改写，全在既有基建上接线。

```
手指按下游戏画面（未命中虚拟手柄任何控件）
  → DmGamepad 登记 C_GAME（touch → 集合序号 = finger_id）
  → recompute 全量推 dm_touch_set（坐标经 dm_ios_game_frame 归一化）
  → hle_touch 锁存 → 游戏 0x1b65260 读 TouchScreenState
  → 游戏自己决定触摸做什么（UI 面板响应范围待真机观察）
```

- 坐标基准：`dm_ios_game_frame()`（front_ios 维护，letterbox/填充/适配几何统一）
- 新增 **背包 / 菜单** 快捷 pill 键（−/± 外侧一档，双布局都有）：语义 = Y / + 的重复入口，游戏内改键后语义跟随真实键
- 诊断：`Documents/env.txt` 加 `DM_TOUCH_LOG=1` 可看逐帧触点

**已知局限（真机验证项）**：
1. hle_touch 面板坐标硬编码 1280×720——适配模式（原生比例渲染）下触摸会被拉伸映射。若游戏读触摸后与渲染尺寸挂钩，需把 1280×720 常量也参数槽化或按 `front_game_res` 缩放
2. 游戏内部**哪些面板消费触摸**未知（D3 主机版官方无触屏）——v1 的核心目的就是真机观察这条
3. 世界层（走路/打怪）大概率不响应触摸（那是光标的事，见 v2）

## 三、触控 v2 路线（已逆向，待实施）

### 3.1 世界层：点哪走哪 / 点哪打哪（路线 B 实施）

静态侦查已完成（§1.3），宿主写入伪代码：

```c
int  pidx  = call_0x89d960();              // 本地玩家索引
int  world_id, tmp;
call_0x8a0360(pidx, &world_id, &tmp);      // world_id = 玩家表项+0x114
void *ws   = call_0x9a0370(world_id);      // 每世界 0x718 结构
void *node = *(void**)(ws + 0x170);        // 光标链表头 = 1P
*(float*)(node + 0x00/0x04/0x08) = wx/wy/wz;
```

- 时序：挂 hle_hid `fill()`（与按键同一样本）；同一样本清右摇杆防打架
- A 键交互原生（光标处施法/拾取），无需额外逆向
- **屏幕→世界反投影**待解：优先观察 `PowerCursorSetToXStick`（0x9de2b0/0x9de440）如何从摇杆域映射到地面平面；v1 可先做**相对模式**（手指拖动 = 光标按屏幕位移移动）
- 长帧/黑屏等异常：写前校验 node 非空、world_id 有效

### 3.2 UI 层：面板触控（背包/菜单/商店）

D3 无鼠标消息捷径，候选路径（按成本排序）：

1. **脚本 VM 调用**（推荐）：UI 事件是 VM 函数（`UI_StashGrid_OnRightClick` 等）。逆向 VM 调用器（按名字/ID 调用），宿主把「点中的控件 → 对应 OnClick(参数)」直调。需要：VM 函数名 → 原生函数指针表（§1.3 注册表模式已找到一处）、控件对象获取（H2O 树）。
2. **H2O 控件树 + 焦点吸附**：逆向 H2O 节点内存布局（.ui 解析后的运行时结构）+ 每帧扫可见控件几何 → 触摸点吸附最近控件 → 合成方向键把焦点挪过去 + A。通用性好但每页焦点图不同，风险在「改设置类页面」（d2r 的教训：焦点页摇杆会改设置）。
3. **.ui 文件重写**（最重）：逆向 deadbeef 分块压缩格式 + 重排节点位置（把血条/技能/地图移到上角，任务②），顺带把触控热区数据写进布局。数天级。

### 3.3 HUD 移位（任务②）与触控的关系

HUD（血球/技能条/地图）移到上角后，下半屏整块让给虚拟手柄 + 世界触控（点地走路）。两个实施顺序：
- 先 v2 世界触控（点哪走哪）→ HUD 移位价值立刻显现
- HUD 移位走 §3.2 路径 1/2（运行时改 H2O 节点位置），不走文件重写
