## 二、拿到 dump 后的离线分析流程（下一轮主线）

1. **验证锚串在不在运行时内存**：python 在 hud-dump.bin 里搜 `ConsoleHUD_main.LayoutRoot`
   （idx 把 guest 偏移映射到文件偏移）。命中 → 找引用指针 → 节点记录 → float 对定位位置字段；
   不命中 → H2O 运行时只存哈希/位打包（静态路线成为唯一路线）。
2. **找布局对象**：锚串地址附近的指针引用（节点记录），顺 +0x1058 位流指针/+0x1060 元素数
   特征扫布局对象。
3. **定位血球/小地图位置字段**：dump 时用户在主城（HUD 可见），记录附近找 1280×720 面板
   坐标系的 float 对（ConsoleHUD Globes 左下 ≈ 小坐标、Minimap 右下 ≈ 大 x 小 y）。
4. **实现移位写值**：hle_hudmove.c 扩展——每帧（或 ui 变化时）把目标节点位置写为左上/右上
   值；`dm_hudmove_set_controller` 已接好（手柄接入自动还原，presence 管线在 DmGamepad.m
   physical_present → dm_hudmove_set_controller）。写值来源 = 启动器配置或编译期常量。
5. **验收**：iPad 触摸模式四角 HUD 上移；插手柄原位；拔手柄再移位。

## 三、静态解析进展（并行线，dump 失败时的唯一路线）

- **.ui 头区格式刷新**（老结论「目录固定 2 条」是错的）：0x20 处 {u32 元素数, u32 值区大小,
  u32 值区偏移}（SinglePlayerFrame: 234/184/0x15060；ConsoleHUD: 66/184/24288）；0xd0 起至少
  6 张 {u64 hash, u32 off, u32 count} 表（0x15170/40、0x151a0/24、0x151f0/112、0x15260/672）。
  字符串区 = 裸 \0 串（OnlinePortraitFrame）+ {u64, u32 off, u32 len} 切片条目混布。
- **锚串教训**：完整路径 `ConsoleHUD_main.LayoutRoot.Globes` 在 .ui 池里不存在（Globes 是
  逐段存名的子节点）；池中实证的完整串：ConsoleHUD_main.LayoutRoot、
  ...hp_bar_template_player、...PlayerSlots。
- **解析链反汇编**（capstone，main.bin 在 `../_scratch/d3_main.bin`，27.9MB，可随时重解压

## 四、CI/构建关键机制（已根治，勿回退）

1. **patches/nxnative.patch 重生成**：`git status --short | grep '^??'` 实时清点（排除
   .dm-pinned、dm/games/<TITLE>/、dm/verify/ 生成物）→ add -N 全部 → `git diff > patch`。
   现为 36 文件（22 改 + 14 新建）。**新文件必须 sed 转 LF**（CRLF 的 Makefile 会让 make 挂）。
2. **快照 zip = 纯孤儿树**（`git archive HEAD` 于子仓库，e3b2411 = bootstrap 精确孤儿快照
   提交，954 文件）——**不含补丁状态**！从工作区打 zip 是错的（内容已被 patch 污染）。
   Release 资产 nxnative-s9579030（curl 匿名直链下载 + ZIP_SHA256 指纹校验）。
3. **bootstrap patch 应用 = 确定性幂等**（dr3.py:183-201）：尽力逆应用（失败忽略）→ 强制
   正向 apply → 静默无效时 `patch -p1 --forward --batch -i` 兜底 → 哨兵校验（lan_native.h
   存在 + hle_hudmove.c 含锚串字面量）。**git 2.56+ 的 --reverse --check 对未应用树误报
   成功**，不可作「已应用」判定。
4. **actions/cache 已整体移除**（workflow）：缓存树过期+假阳性+删除传播延迟三重毒，而
   bootstrap 走 Release 快照零 API，缓存无收益。
5. **LTO strip 字面量**：static const 字符串数组若只被间接引用会被 iOS Release 的 LTO 从
   产物里剥掉——`__attribute__((used))` + 首帧日志直接使用双保险（hle_hudmove.c anchors）。
6. **shell_build.py 内建取证链**：make -n rc/行数 → gen_build 输出全文打印 →
   HEADER_SEARCH_PATHS 精确条目匹配（子串会被 host/gen/<ID> 骗过）→ 树哨兵 → 产物字节级
   锚串 offset。CI 失败直接给原因。
7. iOS 平台源码（DmGamepad.m/front_ios.m）本地无 Mac 编不了，靠 CI 迭代——推前自检
   ObjC 模式（如 `? @` 双重装箱）。ObjC boxed `@(x ? @1 : @0)` 非法 → `@(x ? 1 : 0)`。
