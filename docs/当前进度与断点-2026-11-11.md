## 七、新教训（本轮）

1. **LDR imm12×4=字节偏移**：扫 `ldr w?,[x?,#0x12c]` 要用 imm12=0x4B，直接写 0x12c 会扫到 +0x4b0（120 个真站点差点错过）。
2. **GitHub trees API 递归大查询连跑触发 403 次级限流**（分钟级窗口）；`api()` 重试逻辑当时只认 5xx/429——403 也要长退避（d3e48ae）。同模式短间隔重跑 CI 会叠加限流，失败后先等再跑。
3. **修编译错先确认改的是哪一行**（25a6e45 改错行的教训：同名常量两处使用，报错行号才是准星）。
4. shell_build xcodebuild 失败不吐日志=CI 抓瞎——失败打印尾部 80 行（41e3d8d）已永久解决。
5. **打包前必查 upstream 树是哪个补丁的产物**（bootstrap 幂等只看「补丁已应用」，分不清新旧补丁；`grep season tools/third_party/.../patch_nso.py` 十秒避免打错包）。
6. **改写器功能开关决定产物内容**：`DM_PRIVATE_GATES`/`RULESET`/`DM_RULE_RUN` 关着时 patch_nso 照常成功退出，gates=0 无声无息——**验收只认 structck 的门计数与 gates.tsv 行数**，不认「改写没报错」。
7. **hle.h/patch_nso 都在补丁里=动它们就改 PATCH 指纹**：本地验证工具（structck/equiv，zip 基线+运行时产物，惯例不入补丁）可自由扩展；验证不过先想「能否只动工具不动补丁」。
8. **Windows 做包环境**：spirv-cross（dm-tools/SPIRV-Cross/build）与 LLVM_BIN（scoop llvm）都不在缺省 PATH；`grep`=ugrep；verify/equiv.py 是 fork 专设计（argparse 在模块顶层+worker 依赖继承全局），Windows 只能 --skip-verify 跳过等价验证、靠 structck 结构校验兜底。
